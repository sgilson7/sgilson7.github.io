Concept

GenAI-Assisted Prototyping Procedure

The GenAI-Assisted Prototyping Procedure is a nine-stage pipeline, brief to handoff, in which a person reads the plan, plays the build, and deploys it.

A working practice from one guest lecture, drawn from building five browser artefacts. Every stage names the prompt or autopsy step it is carrying out.

Five browser artefacts came out of this, so the shape is a worked practice rather than a proposal.

A person writes the brief: what is being made, what done means, and what the agent may not decide alone. The agent turns that into a plan with a reason attached to every decision, and writes no code until a person has read it. Then it measures against the running build instead of against its own memory, and says in the commit what it found. Tests and content lints land with the change they cover.

While the work happens the agent keeps a notebook, one row per assumption, each marked as a divergence, a finding, or something handed back for a person to decide. Then a person plays the thing for a fortnight, and everything wrong becomes a row. A person deploys, and the browser gate walks the live page. Last comes a handoff written for whoever picks it up, listing the rules that are load-bearing and the mistakes that cost a day.

The agent never pushes. That is the line the whole arrangement rests on.

Nearby terms in the literature: human-in-the-loop development, pair programming, agentic workflows. None of these is a synonym for GenAI-Assisted Prototyping Procedure; they name related work this paper did not measure against.
