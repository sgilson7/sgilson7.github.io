Builder

Research tool

Builder is the setting I use to build browser tools with a coding agent. A tool's rules live in a Rust core that performs no input or output, so its tests run in seconds without a browser. A thin WebAssembly shim moves values between that core and the page and decides nothing, and a static page draws what the core returns.

The repository holds a template to copy when starting a tool, the instructions a coding agent reads at the start of each session, the nine stages of the build procedure as files in every project, and one command that runs the whole check. The check covers formatting and lint, the core's tests, boundary tests that fail when the core does input or output or the shim makes a decision, the release WebAssembly build, an audit that follows each of the module's imports into its JavaScript glue, and a browser check in Chromium, Firefox and WebKit that fails on a console error or a request to another origin. A pass describes what happened on the path the check drove. It does not show that a feature the check never started cannot reach the network, and a script in the repository plants defects to show that each check fails when it should.

The link below opens the repository's minimal example, a counter that exercises every part. Feedback Drafts was built from the template by a fresh agent session given one prompt set, and the repository includes that prompt set.

Using the setting

Clone the repository, copy template/ to a new directory, write BRIEF.md, and point a coding agent at the directory. ./scripts/check.sh runs the full check before a deploy.
